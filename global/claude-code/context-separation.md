# コンテキスト運用（Claude Code 固有）

`plugins/ore-rules/rules/` に置いた共通規約と違い、ここは **Claude Code のセッション機構**
（`/clear`・スキル・サブエージェント）に依存するため、Devin には配布しない。

## 設計→実装のコンテキスト分離（トークン節約）

- 設計・方針の議論が完了したら、決定事項を必ず Markdown にドキュメント化して
  プロジェクトの `docs/` に保存する（背景 / 決定内容 / 理由 / 実装方針）
- 保存後はセッションを `/clear` し、新しいセッションでそのドキュメントを読み込んでから
  実装を開始する
- 会話履歴を実装フェーズに持ち越さない — コンテキストはドキュメント経由で引き継ぐ
- 長引いたセッションの途中チェックポイントには **context-optimizer** スキルを使う

> サブエージェントへの委譲（efficient-fable）については、`~/.claude/CLAUDE.md` 末尾の
> `@agent-native/skills` 管理ブロックが自動で挿入するため、ここには書かない。
> 二重に持つと片方が古くなる。

## プロジェクト運用規約の参照先

判断基準そのものは `plugins/ore-rules/rules/project-governance.md` にある。
docs 構成・タスク管理・CI・並行作業の**具体的な手順**が必要になったら
**project-governance** スキルを読み込む。

読み込むタイミング:

- docs 構成 / タスク管理 / CI / 並行作業の方針を決めるとき
- 「ドキュメントが多すぎる」「進行状態がどこにあるか分からない」「規約が守られていない」
  と感じたとき
