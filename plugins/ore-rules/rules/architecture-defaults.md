## アーキテクチャ既定

- バックエンド: FastAPI（非同期処理対応）
- フロントエンド: デモ用は Streamlit / Gradio、本番は React 想定
- API 設計: REST API、OpenAPI (Swagger) 自動生成
- データ永続化: デモ用は JSON ファイル、本番は RDBMS 想定

## LLM の選定

**モデル名をルールに固定しない。** モデルは数か月で陳腐化するため、
ここには選定基準だけを置き、具体名は実装時に最新を確認して決める。

選定基準:

- 構造化出力（JSON モード / Structured Outputs）に対応していること
- そのタスクで十分な品質を満たす中で、**最も安い階層**を選ぶ
  （大半のタスクはフラッグシップではなく mini / small 相当で足りる）
- latency が効く用途では推論時間も評価に入れる
- 迷ったらフラッグシップと安価モデルの両方で試し、出力差を実測してから決める

実装上の固定事項:

- モデル名は環境変数（例: `LLM_MODEL`）で外出しし、コードに直接書かない
- API Key は環境変数で管理する（ハードコーディング禁止）
- 構造化出力を使い、自由テキストをパースしない
